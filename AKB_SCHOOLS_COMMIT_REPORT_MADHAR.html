Prior versions relied on static JSON storage. To eliminate disk contention during peak billing hours, Lead Engineer ZERO_BOOK_13\madhar introduced a high-concurrency MySQL connection pool and versioned migration engine.

3.1 Managed MySQL Connection Pool (config/database.js)
const mysql = require('mysql2/promise'); const pool = mysql.createPool({ host: process.env.DB_HOST || 'localhost', port: parseInt(process.env.DB_PORT || '3306', 10), user: process.env.DB_USER || 'akbschools_user', password: process.env.DB_PASSWORD || 'SecurePass2026', database: process.env.DB_NAME || 'akbschools_db', waitForConnections: true, connectionLimit: 15, queueLimit: 0 }); module.exports = pool;
3.2 Programmatic SQL Migration Engine (scripts/migrate.js)

During server startup or automated deployments, the system executes an idempotent migration runner:

  • Database & Table Creation: Executes versioned DDL statements (v1.0.0 to v1.0.10) creating tables for students, payments, users, attendance, expenses, audit_logs, and app_settings.
  • Audit Columns Injection (Commit 9267751): Automatically adds audit tracking fields (created_at, updated_at, created_by) across all relational entities.
  • Resilient Local IndexedDB Fallback: If network drops occur, the SPA switches seamlessly to client-side IndexedDB persistence, syncing changes when connectivity recovers.

AKB SCHOOLS PAGE 4 — PERFORMANCE & SECURITY
4. High-Performance Synchronization & Pure-JS Cryptography

In initial builds, batch updating student records (PUT /api/students) executed sequential single-row MySQL queries, causing 13.5-second latency. Lead Engineer ZERO_BOOK_13\madhar refactored the pipeline in Commit 3ea465a, achieving a 450x speedup (~30ms response time).

4.1 Optimized Non-Blocking Parallel Execution Excerpt (server.js)
// Optimized Parallel Query Pipeline by ZERO_BOOK_13\madhar (Commit 3ea465a) app.put('/api/students', async (req, res) => { const students = req.body; if (!Array.isArray(students)) return res.status(400).json({ error: 'Invalid payload' }); try { const updatePromises = students.map(student => { const sql = "UPDATE students SET name=?, class=?, section=?, parent_phone=?, updated_at=NOW() WHERE id=?"; return db.query(sql, [student.name, student.class, student.section, student.parent_phone, student.id]); }); await Promise.all(updatePromises); setImmediate(() => saveLocalBackup(students)); res.json({ success: true, count: students.length, message: 'Batch sync complete in ~30ms' }); } catch (err) { res.status(500).json({ error: err.message }); } });
4.2 Pure-JS Cryptographic Hashing Fallback (assets/js/utils.js)

In non-HTTPS network origins (LAN IP addresses like http://192.168.1.50:3000), browser Web Crypto APIs (window.crypto.subtle) are blocked. ZERO_BOOK_13\madhar engineered a pure JavaScript PBKDF2 fallback algorithm (Commits 3ac297d & 4b0b44d), ensuring login capability on all LAN terminals.

// Pure-JS PBKDF2 Fallback Algorithm (Commit 4b0b44d) function pbkdf2PureJS(password, saltHex, iterations, keyLenBits) { var salt = hexToBytes(saltHex), blockCount = Math.ceil((keyLenBits / 8) / 32), derivedKey = []; for (var i = 1; i <= blockCount; i++) { var blockInput = new Uint8Array(salt.length + 4); blockInput.set(salt, 0); blockInput[salt.length + 3] = i; var u = hmacSha256(password, blockInput), t = new Uint8Array(u); for (var j = 1; j < iterations; j++) { u = hmacSha256(password, u); for (var k = 0; k < t.length; k++) t[k] ^= u[k]; } for (var m = 0; m < t.length; m++) derivedKey.push(t[m]); } return bytesToHex(derivedKey.slice(0, keyLenBits / 8)); }

AKB SCHOOLS PAGE 11 — OPERATIONAL GUIDES
11. Operational Guides for Cashiers & Administrators
11.1 Cashier Billing & Receipt Workflow
  1. Log in using cashier/accountant credentials (account1 / account2).
  2. Search student record by Admission Number or Name (Ctrl + F).
  3. Select relevant fee heads (Tuition, Exam, Transport). System auto-splits revenue ledgers.
  4. Select Payment Mode (Cash / UPI / Cheque) and click Save & Print Receipt.
  5. System automatically prints dual A5 receipt (Office & Parent Copy) and triggers paper cut.
11.2 Teacher Attendance & Academic Workflow
  1. Log in using assigned teacher account (teacher).
  2. Navigate to Attendance Portal (#attendance), select Class and Date.
  3. Mark student status (Present / Absent / Late / Holiday) and click Submit Attendance.
  4. For Report Cards, navigate to #reports, enter examination marks, and click Save.
